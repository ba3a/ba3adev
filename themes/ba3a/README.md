# Theme of ba3a.dev

The crisp, professional look of `ba3a.dev`: a cool slate palette with one teal
accent, Manrope for headings and the site name, and a compact header with the
site name as a wordmark. It changes only what it has to; everything else is
coffer's default theme (see `github.com/ba3a/coffer/blob/v0.1.0/docs/themes.md`).

| File | What it does |
| --- | --- |
| `assets/ba3a.css` | Overrides coffer's colour and font custom properties for light and dark (`prefers-color-scheme` and the theme switch), declares the web font, and styles the compact header. |
| `templates/base.njk` | `{% extends "coffer:base.njk" %}`. Overrides the `head` block (with `super()`, to add the stylesheet and the font preload), the `footer` block (with `super()`, to link the word "coffer" of the credit line to `/made/coffer/`) and the `nav` block of the header. The wordmark and the theme switch are the engine's own markup, restyled by the stylesheet. Only the navigation is replaced here. |
| `templates/project-tool.njk`, `templates/partials/landing.njk`, `templates/partials/landing-facts.njk`, `templates/partials/landing-accent.njk`, `assets/landing.css`, `i18n/en.yaml` | The landing layout of a tool page whose text has section markers (specloop and coffer). See [A landing page](#a-landing-page). Any other tool page is rendered by the engine as before. |
| `assets/brand/` | The logo and the favicons of the site: the letter B with a `>` prompt cut out of it, in teal. Generated by `scripts/make-ba3a-brand.mjs` (see [Brand](#brand)). |
| `theme.yaml`, `card.svg.njk`, `fonts/` | The title card for link previews: dark slate with the site accent, set in Manrope Bold. |
| `assets/fonts/` | The self-hosted Manrope web font files, the Inter and JetBrains Mono files of the landing layout, and the license texts of Manrope, Handjet, Inter and JetBrains Mono (`OFL.txt`, `OFL-Handjet.txt`, `OFL-Inter.txt`, `OFL-JetBrains-Mono.txt`). The Handjet font file itself is in the Faultory project folder. |

The stylesheet also turns off synthetic bold on the game page (`.game-page`), which has the display font described under [Handjet](#handjet-the-page-of-faultory).

UI strings are coffer's English defaults, except the few words of the landing layout in `i18n/en.yaml` (shared ones, and one group per landing page under its slug).

## Colours

The palette is defined once, in `assets/ba3a.css`. Every colour pair that the
engine's components use (body, muted and link text, text on an accent button,
code, control borders, the focus outline) is checked for WCAG 2.x AA contrast in
light and dark by `scripts/site-test/ba3a-theme.test.mjs`, which reads the
values from the stylesheet. Change a colour there and `npm run test:sites` tells
you whether it still passes.

## Brand

The mark is a capital B with a command-line prompt, `>`, cut out of its body:
a letter for the site, a shell prompt for the developer. The chevron is a real
hole (an even-odd sub-path of the letter), so the page shows through it. The
letter is teal (`#4fc8df`, the accent of the dark scheme) on slate (`#0c1320`,
the colour of the dark page and of the title card).

| Where | Light | Dark |
| --- | --- | --- |
| Header mark, `logo.svg` / `logo-dark.svg` | letter on a slate rounded tile | bare letter, no tile |
| Browser tab, `favicon.svg` | tile | bare letter (switches on `prefers-color-scheme`) |

The bare letter has no background, so it only works on a dark page; the tile
works on a light one. The stylesheet draws the mark in front of the site name
(`.site-title::before`) in four rules, like the colours: light, dark by system
preference, dark and light by the theme switch.

`node scripts/make-ba3a-brand.mjs` writes everything in `assets/brand/`:

| File | Use |
| --- | --- |
| `favicon.svg` | The icon of modern browsers: the tile on a light tab, the bare letter on a dark one. |
| `favicon.ico` | 16, 32 and 48 px, with the tile, for browsers and tools that cannot use the SVG. |
| `apple-touch-icon.png` | 180 px, full bleed (iOS rounds the corners). |
| `icon-192.png`, `icon-512.png` | App icons, with the tile. |
| `logo.svg`, `logo.png` | The mark on the tile (512 px for the PNG). |
| `logo-dark.svg`, `logo-dark.png` | The bare letter, transparent (512 px for the PNG). |

`templates/base.njk` links the `.ico` first (`sizes="any"`), then the SVG, then
the apple touch icon. The landing page of a project links its own pictures
instead (`assets/<slug>/`), and the base template leaves the site's out there, so
the browser never has two sets to choose from. The chevron is the fine detail of
the mark, so the small raster sizes get a heavier one. Do not edit the files by
hand: change the script and run it again; `scripts/test/make-ba3a-brand.test.mjs`
checks that the committed SVG files are the generated ones. The mark is drawn
from plain shapes: there is no font and no third-party artwork in it.

## Navigation

The header lists the links in the `nav` that coffer builds for the page, except
the home link, because the wordmark already links home. The Projects entry
therefore appears as soon as the site has projects (`projects` in `coffer.yaml`)
and links to the projects index, and a site without projects has no link to a
page that does not exist.

## Fonts

Manrope, weight 700 (Bold), is the only font file of the theme, and the only one that pages load, except the page of Faultory, which also loads Handjet (see below).

- Designer and license: The Manrope Project Authors, SIL Open Font License 1.1.
  The license text and copyright line are in `assets/fonts/OFL.txt` and
  `fonts/OFL.txt`.
- Upstream: <https://github.com/sharanda/manrope>.
- Source of the files: the npm package `@fontsource/manrope` version 5.3.0
  (<https://www.npmjs.com/package/@fontsource/manrope>), files
  `files/manrope-latin-700-normal.woff2` and
  `files/manrope-latin-ext-700-normal.woff2`, copied unchanged to
  `assets/fonts/manrope-latin-700.woff2` and `assets/fonts/manrope-latin-ext-700.woff2`.
  `OFL.txt` is the `LICENSE` file of that package.
- `fonts/Manrope-Bold.ttf` is for the title cards only: the card renderer does
  not read woff2. It is the two woff2 files above converted to TrueType and merged
  into one file with fontTools 4.25 (`fontTools.merge`); no glyph is changed. It
  is not served on the site.
- The pages load no font from another host. The font is declared with
  `font-display: swap` and a system sans-serif fallback stack.

## Handjet, the page of Faultory

The page of a game may set its own accent colour and display font (see
`github.com/ba3a/coffer/blob/v0.1.0/docs/projects.md`). Faultory uses Handjet Bold for its headings and
buttons. coffer publishes a project's font file only from the project's own
folder (a font from the theme is not supported), so the font is **not** in this
theme: it sits in `content/ba3a.dev/projects/faultory/`, is declared there by
`displayFont` and `displayFontFile` in `project.yaml`, and the engine writes the
`@font-face` rule (with `font-display: swap`) into that page only. The headings
fall back to this theme's heading font (Manrope, then the system sans-serif) while
the font loads or if it does not. The only thing the theme adds is the rule in
`assets/ba3a.css` that keeps the browser from drawing a second, synthetic bold on
top of the font's own bold.

- Designer and license: The Handjet Project Authors, SIL Open Font License 1.1,
  `Copyright 2018 The Handjet Project Authors (https://github.com/rosettatype/Handjet/)`.
  No Reserved Font Name is declared. The license text is

- Source of the file: the npm package `@fontsource/handjet` version 5.3.1

## A landing page

A tool page whose `index.md` has section markers (`<div class="section-marker" id="hero"></div>`) is laid out as a landing page; the two conventions of the text are described in [AUTHORING.md](../../AUTHORING.md#a-landing-page). coffer has no hook between the Markdown and the template, and its renderer drops HTML comments, so `partials/landing.njk` cuts the rendered text at the markers and reshapes each section with regular expressions (the table into cards, the lists into a timeline, a feature grid and stat tiles, the quote into a chat, the `###` questions into `<details>`). `assets/landing.css` is loaded by that page only and every rule is scoped to its `.landing` wrapper, so no other page changes. The wrapper also sets the engine's `--coffer-*` variables to the landing palette, so the facts box and the devlog posts at the end of the page match.

The palette is the one of the style guide of the specloop page, with two additions that WCAG AA asks for and the guide does not have: `--accent-text` (a darker rust for small accent text on the light page, where `--accent` is 4.0:1 on the alternating background) and `--on-accent` (dark text on the orange buttons in the dark scheme, where white is 2.5:1). `scripts/site-test/specloop-landing.test.mjs` reads the tokens from the stylesheet and checks every pairing.

Each landing page has the wrapper class `landing-{slug}`. The accent palette is the `accent: { light, dark }` of the front matter of the landing file (keys `accent`, `accent-text`, `accent-soft`, `term-accent`, `on-accent`, each a `#rgb` or `#rrggbb` colour). `partials/landing-accent.njk` sets the valid ones as `--accent-light-<key>` and `--accent-dark-<key>` in the `style` of the wrapper, and `landing.css` picks the pair of the active scheme, with its own palette as the fallback, so a landing without `accent` (or without a key) shows the default (the rust of specloop) and a new landing needs no CSS. coffer's gold is `#9a6b1f` on light and `#d9a84e` on dark; `scripts/site-test/coffer-landing.test.mjs` and `specloop-landing.test.mjs` read the palette from the fetched file and check that it is the colours of the logo files and that the pairings keep AA contrast. What else differs between pages is the `layout` in the front matter of the landing file of the project (which element is the visual of each two-column section, the kind of terminal of the hero and dogfood sections, the label of a timeline step, where the name in the top bar is split for its accent, and the strings the layout adds). The layout has no table of its own: a setting the file lacks is the default of `partials/landing.njk`, and the default strings are `landing.default` in `i18n/en.yaml`.
